# CREWFLOW — PREMIUM FRONTEND DESIGN & DEVELOPMENT

## 1. Project Overview

Build a complete, modern, premium-quality frontend for **CrewFlow**, an AI-powered multi-agent orchestration and automation platform.

CrewFlow allows users to interact with an intelligent orchestrator that understands user requests, creates execution plans, delegates tasks to specialized AI agents, coordinates their work, monitors execution, and delivers verified results.

This is not a conventional chatbot application.

It should feel like a sophisticated AI workforce management platform and an intelligent operating system for managing autonomous agents.

The frontend must communicate:

* Intelligence
* Reliability
* Transparency
* Control
* Productivity
* Technical sophistication

The final product should look like a professionally designed SaaS startup product that could compete with established developer tools.

IMPORTANT:
Next.js and Tailwind CSS are for the web application.
Flutter is for the native mobile application.

Do not attempt to combine Flutter widgets with Next.js components.

Both applications must communicate with the same backend through a shared API contract.

## 3. Design Philosophy

The most important requirement is that the application must NOT look AI-generated.

Avoid the typical generic AI SaaS aesthetic.

Do not use:

* Purple-to-blue gradient backgrounds.
* Excessive neon colors.
* Glowing borders everywhere.
* Random floating geometric shapes.
* Floating orbs.
* Random animated particles.
* Unnecessary glassmorphism.
* Excessively rounded cards.
* Rainbow gradients.
* Generic AI robot illustrations.
* Decorative animations without purpose.
* Oversized gradient typography.

Instead, use design inspiration from:

* Linear
* Vercel
* Raycast
* Stripe Dashboard
* Arc Browser
* Notion

Do not copy their interfaces. Use their design discipline, spacing, hierarchy, and interaction quality as inspiration.

The design should feel understated, precise, editorial, and premium.

## 5. Animation and Interaction Guidelines

The application should feel modern and animated, but never distracting.

Use Framer Motion for web animations.

Use Flutter's native animation system for mobile.

Allowed animations:

1. Smooth page transitions.
2. Sidebar expansion and collapse.
3. Dropdown animations.
4. Modal entrance and exit.
5. Subtle hover interactions.
6. Button press feedback.
7. Progress bar transitions.
8. Task status transitions.
9. Agent execution state transitions.
10. Smooth tab switching.
11. Skeleton loading animations.
12. Subtle chart entrance animations.

Animation timings:

* Micro interactions: 120–180ms.
* Dropdowns: 160–220ms.
* Page transitions: 180–260ms.
* Larger transitions: 250–350ms.

Use natural easing.

Respect prefers-reduced-motion.

IMPORTANT HERO PAGE RULE:

Do not add any random moving shapes, floating circles, animated orbs, particles, floating cards, or decorative geometric objects.

The hero section must remain visually clean.

Its animation should come from purposeful interface interactions, such as:

* A live execution preview.
* A carefully designed task progression.
* A subtle cursor interaction.
* A static, polished product screenshot.
* A controlled agent workflow demonstration.

No random movement for decoration.

## 9. Command Center

This is the central product experience.

Design a conversational interface that is more sophisticated than a traditional chatbot.

Layout:

* Conversation sidebar.
* Main conversation area.
* Optional execution context panel.

Features:

* New request.
* Conversation history.
* Message composer.
* File attachment interface.
* Execution plan preview.
* Agent delegation visualization.
* Approval requests.
* Final output display.

When a user enters a request, display a structured execution plan.

Example:

User:
"Research five competitors and create a comparison report."

CrewFlow:
"I've broken this request into four execution steps."

1. Identify competitors.
2. Research relevant information.
3. Build a comparison.
4. Review and prepare the final report.

Show which agents are assigned to each step.

The interface must visually distinguish:

* Thinking/planning.
* Awaiting approval.
* Executing.
* Completed.
* Failed.

Never present fake execution as actual backend execution.

## 20. Development Rules

1. Inspect the existing repository before modifying anything.
2. Preserve existing backend integrations.
3. Do not replace functioning backend logic.
4. Do not invent API endpoints.
5. Create reusable components.
6. Use TypeScript strict mode.
7. Keep API communication inside service modules.
8. Maintain clear separation between UI and business logic.
9. Avoid massive single-file components.
10. Use consistent naming conventions.
11. Ensure loading, error, empty, and success states.
12. Add keyboard accessibility.
13. Support reduced motion.
14. Validate responsive behavior.
15. Avoid unnecessary dependencies.
16. Do not leave non-functional buttons pretending to be implemented features.
17. Use mock data only where actual backend data is unavailable.
18. Never expose secret API keys in frontend code.

## 22. Implementation Strategy

Do not generate the entire application in one massive implementation.

Work in phases.

PHASE 1:

* Inspect repository.
* Understand existing backend.
* Establish Next.js frontend.
* Create design tokens.
* Build global application shell.
* Build marketing homepage.

PHASE 2:

* Build authentication.
* Build dashboard.
* Build command center.
* Connect available APIs.

PHASE 3:

* Build Agent Hub.
* Build Task Manager.
* Build Activity Center.

PHASE 4:

* Build Workflow Studio.
* Build Memory Center.
* Build Integrations.
* Build Settings.

PHASE 5:

* Develop Flutter application.
* Connect shared APIs.
* Implement mobile navigation.
* Implement mobile core features.

PHASE 6:

* Test everything.
* Fix responsive issues.
* Improve animations.
* Optimize performance.
* Prepare production build.

At the beginning, inspect the existing project and report:

1. Existing repository structure.
2. Existing frontend and backend technologies.
3. Existing API endpoints and integration points.
4. Potential conflicts with the requested stack.
5. Recommended implementation sequence.

Then start implementing Phase 1.

**FINAL DESIGN DIRECTION:**

CrewFlow must look like a serious, premium, modern software product.

Think Linear's precision, Raycast's interaction quality, and Vercel's visual restraint.

Do not make it look like another generic AI dashboard.

Every visual element must serve a functional purpose.
